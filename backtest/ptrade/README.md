# PTrade 回测操作清单 & 运行登记表

本文件是 PTrade 回测的**长期操作清单**与**运行登记表**:
- 上半部分（§一~§三）：每次回测怎么跑、怎么导出、怎么归档——可重复照做。
- 下半部分（§四）：每次回测的参数 + 结果路径 + 关键指标对照表。

> ⚠️ **原始 `Log.txt` 不入 git**（体积大，被 `.gitignore` 排除）。因此**关键指标必须登记到 §四 的表**——
> 那张表才是回测结果的**持久档案**。截图与交易/持仓 CSV 入库，原始日志只在本地。

---

## 一、操作步骤（每次照做）

1. 打开 PTrade，新建/选择策略，粘贴 `deploy/ptrade_quality_momentum_top1.py` 全文。
2. 改文件顶部常量设置本次参数：
   - `REBALANCE_DAYS` = 要测的调仓窗口（1 / 2 / 5 …）
   - `COMMISSION_RATIO` = 回测佣金率（默认 `0.00005` = 万0.5，本账户真实费率）
   - 其余保持默认（`WINDOW=20`、`INVEST_RATIO=0.98`、`REBALANCE_MODE="min_hold"`）
3. 回测设置：**频率 = 日线**（务必，分钟频率慢一个数量级且无收益）；区间 = `2014-01-01 ~ 今`（或所需区间）；起始资金随意（指标按比例，与资金量无关）。
4. 跑完导出四样：`Log.txt`、收益曲线/月度热力图**截图**、`交易详情*.csv`、`持仓明细*.csv`。
5. 归档：在 `backtest/ptrade/` 下新建文件夹 `<佣金码>_rd<N>/`（见 §二），把四个导出文件放进去。
6. 登记：在 §四 表加一行（参数 + 路径 + 关键指标）。指标可让 Claude 解析 `Log.txt` 自动算出。
7. 提交：`git add backtest/ptrade/<新文件夹>/` + 本 README（CSV+截图入库，`Log.txt` 自动忽略）。

---

## 二、文件夹命名规范

`c<佣金bp>_rd<N>[_<备注>]`

- 佣金码：`c05` = 万0.5（0.005%）、`c20` = 万2（0.02%）
- 示例：`c05_rd1` = 佣金万0.5、`rebalance_days=1`
- 旧归档 `rd2/`、`rd5/` 是**万2（c20）**口径，保留原名不动

## 三、指标口径

- 指标由 `Log.txt` 每日「总资产」序列**独立计算**：总收益、CAGR、年化波动、Sharpe（rf=0，年化 252）、最大回撤；成交笔数取「交易详情」CSV 行数。
- 默认区间 `2014-01-02 ~ 末日`；「近3年」指 `2024-01 ~`。
- 因 `Log.txt` 不入 git，**§四 表中的指标即权威记录**——跑完务必回填。

## 五、本地引擎交叉验证（框架 `backtest/runner.py`，非 PTrade）

> 本地框架引擎跑的结果，作 PTrade 的**独立交叉验证**。执行模型不同（框架 T+1 开盘成交 + `commission_ratio` 佣金近似 vs PTrade 日线 bar），**方向一致、数值不逐位相同**。`commission_ratio = 0.00005`（万0.5），区间 2014-01 ~ 2026-06。

| 运行 | rd | 佣金 | 总收益 | CAGR | Sharpe | 最大回撤 | 执行次数 | 近3年收益 | 近3年Sharpe |
|------|----|----|----|----|----|----|----|----|----|
| 本地 rd=1 | 1 | 万0.5 | +3539.6% | 33.81% | 1.29 | −28.55% | 487 | +248.1% | 1.70 |
| 本地 rd=2 | 2 | 万0.5 | +3194.1% | 32.73% | 1.26 | −28.41% | 395 | +230.1% | 1.63 |
| 本地 rd=5 | 5 | 万0.5 | +2876.4% | 31.64% | 1.23 | −25.77% | 273 | +192.3% | 1.49 |

**结论**：真实费率（万0.5）下 **rd=1 > rd=2 > rd=5**，收益与 Sharpe 单调；近3年 rd=1 收益/Sharpe/回撤三项全优；归因广谱（创业板+黄金+纳指）。代价：rd=1 全周期回撤最深、换手最高（最吃 regime）。
**待办**：PTrade 在万0.5 下重跑 `c05_rd1/2/5` 确认（§四 表）；若 rd=1 复现胜出 → 走 §3.6 流程立新 changelog 条目，将实盘基准由 rd=2 改为 rd=1，并据 rd=1 换手特征收紧「天气预报员」whipsaw 阈值。

## 六、逐日对账 harness（信号/持仓逻辑迁移的硬指标）

`reference/` 下是**框架侧**每日 (score, held, positions) 的 committed CSV fixture;
`rd2/`、`rd5/` 是 **PTrade 侧**实盘导出。两者由 `tests/test_ptrade_reconciliation.py`
做逐日三维对账(score / Top1 / 持仓)。容差内全绿只表示逻辑迁移完成；交易模式还需通过
`tests/test_ptrade_execution_state.py` 与模拟盘完整换仓 gate，分层定义见 `../../CONTRACT.md`。

- **跑测试**:`uv run pytest tests/test_ptrade_reconciliation.py -v -s`(`-s` 看 held 分歧段清单)
- **刷新 fixture**(改了策略/因子/`data/db` 数据后):`uv run python scripts/export_framework_reference.py`,
  再 review CSV diff 并回填 `reference/MANIFEST.md` 的数据快照。
- **设计 / 口径 / 容差**:见 `reference/MANIFEST.md`、`../../CONTRACT.md` §3、
  `../../docs/plans/2026-06-21_ptrade_reconciliation_harness.md`。

> ⚠️ fixture 由本地 `data/db`(junction)生成。**勿删 main worktree**,否则 junction 悬空、无法刷新。
