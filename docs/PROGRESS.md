## 四、待办 / 风险点

1. **🟡 「天气预报员」rd=5 影子组合脚本（落地监测协议）**
   §3.6 的监测协议目前是文档约定，靠人记着对比不可靠。需写脚本：复用回测引擎，定期（周/月）用最新数据同时算 rd=2（实盘账本）与 rd=5（影子）滚动净值，自动输出三类信号读数（whipsaw / 滚动回撤 / 影子相对表现），达阈值钉钉预警。**这是把 regime 监测自动化的关键一步。**

2. **🟡 测试 rd=1 + 校准真实佣金（万0.5）**
   既然含成本下 rd=2 优于 rd=5，且实盘 ETF 佣金实为**万0.5**（回测用的万2 高估了摩擦），更高换手在实盘可接受。需在**万0.5**口径下重跑 rd ∈ {1, 2, 5}，做干净对比，判断是否切到 rd=1。若 rd=1 胜出 → 走 §3.6 同款流程立新 changelog 条目。

3. **🟢 §3.2 交易成本模型（框架侧）** —— PTrade 回测已提供"含真实成本"结论，§3.2 的评估目的**基本达成**；但框架自身回测引擎仍未内置成本模型，若要在框架侧复现含成本回测仍待补（优先级已降）。

4. **🟡 滞后阈值扫描（Hysteresis threshold scan）** —— 设计稿与实施计划在 `docs/superpowers/plans/2026-05-22-...`，尚未落地。
