§1 / Overview

这是一个什么项目

一个自建的量化框架（刻意不用 Backtrader / QLib 等重型框架），面向少量大规模 ETF、日线级别的趋势轮动策略。设计哲学来自「机制与策略分离、接口先于实现、复杂性预算」。

🧩新增因子收敛到一个文件

🔁回测与实盘同源

回测引擎每天只把 df[df.date <= t] 喂给因子，前视偏差被引擎强制杜绝，不依赖因子作者自觉。

📋过拟合护栏内建

参数集中声明、train/test 自动切分、实验日志强制全量记录、等权基准对比——复杂度必须用超额收益「支付」。

§4 / Strategy

策略都做些什么

部署中的是 质量动量 Top1：在 4 只 ETF 里，每次全仓持有「质量动量」得分最高的那一只，按固定窗口轮动。

核心因子：质量动量（Quality Momentum）

动量本身奖励涨得多的资产，但「涨得多」可能靠少数几根大阳线拉起来——这种趋势脆弱。质量动量用 Kaufman 效率比率（ER）惩罚颠簸路径，奖励「干净的趋势」（温水煮青蛙式的平滑上涨）。

momentum = close.pct_change(20)
ER = |closet − closet−20| / Σ20|close.diff()|
score = momentum × ER
ER ∈ [0,1]：≈1 路径像直线；≈0 靠少数跳变拉起。同样 20% 涨幅，一路直线上涨的 score 高于震荡上涨的。
理论来源：Wesley Gray《Quantitative Momentum》Frog-in-the-Pan · Robert Carver《Systematic Trading》

三种持仓策略（同一因子，不同组合规则）

Top1 部署中

全仓得分最高的单一资产。忽略 factors[0] 之后的因子。当前实盘用它。

TopN

等权持有得分最高的 N 只。候选「行业轮动」配置用它在 25 只行业 ETF 上选 Top5。

MomentumRotation

多因子 rank 加权组合器：各因子排名 × 权重求和后归一化。框架最初的默认策略。

§5 / Runtime

运行细节

信号与成交时序（回测与实盘统一约定）

T 日收盘后：基于 T 日及之前数据生成 score  →  T+1 日开盘：执行调仓，成交价 = T+1 开盘价
回报归属：T 日隔夜跳空 → 旧标的（尚未换出）；T+1 开盘后收益 → 新标的
rebalance_days：T+1 调仓后，至少持有 N 个交易日才能再次评估切换

实操对应：卖出在 9:20–25 集合竞价挂跌停价、买入挂略高于开盘指示价，成交价 ≈ 开盘价。因仅交易大规模 ETF，实操滑点接近零。回测引擎 runner.py 精确实现了这套「隔夜归旧仓、日内归新仓」的开盘执行语义。

未来信息隔离（核心护栏）

for t in trading_days:
    truncated = df[df["date"] <= t]      # 引擎强制截断——因子只能看到过去
    series = factor.compute(truncated.copy())
    validate(series, truncated, metadata)  # 输出校验：长度/索引/NaN 位置
    score = series.iloc[-1]               # 只取 t 日的值

两个运行入口

🔬 run_backtest.py

逐日遍历资产并集交易日 → 截断喂因子 → 策略生成目标权重 → 按开盘执行语义累计日收益 → train/test 切分 + 过拟合警告（train Sharpe > 2× test）→ 等权基准对比 → quantstats HTML + 实验日志 YAML。

支持 --from-log 一键复现、--baseline-config 用另一策略当基准、end: "today" 跑到当天。

📡 run_daily.py

① 同步数据 + 新鲜度检查（落后 ≥2 交易日报错）→ ② 读持仓账本 → ③ 算今日因子 → ④ 策略出信号 → ⑤ hold 窗口过滤（在 rebalance_days 内则压制信号）→ ⑥ 执行层 diff → ⑦ 钉钉推送 → ⑧ 仅在真调仓时写回持仓账本。

持仓账本维护 YTD 账本（开盘进/开盘出的分段收益链），供钉钉「年初至今」播报。

辅助：backfill_ytd.py（YTD 补账）

机器没每天跑 run_daily 时，用它重放今年信号、重建 state/{strategy}_position.json，让钉钉「年初至今」按实盘账本口径计算。补账逻辑与回测引擎、实盘严格一致（信号日收盘数据、次日开盘调仓、隔夜归旧仓/日内归新仓、遵守 rebalance_days）。

⚠️ 已知运行隐患：run_daily.py CLI 默认 config 仍指向 momentum_rotation.yaml，裸跑会 fallback 到 rebalance_days=1。实盘正确性当前依赖调度命令显式传 --config quality_momentum_top1.yaml。建议改默认或让裸跑报错。

§8 / Governance

治理规约

strategy_changelog 不是流水账，而是一套防过拟合、防情绪化调参的治理机制。

✓ 维护规则

① 任何对策略本质/参数/引擎的变更必须记录
② 变更必须先有回测对比，后实施（bug 修复除外）
③ 单次变更间隔 ≥ 2 周，单月 ≤ 2 条
④ 重构与诊断不进日志
⑤ 每年 1 月年度审视时作为输入材料回顾

✗ 反模式警示

基于近 1–3 月表现调参（回撤情绪驱动）
无回测对比凭直觉改
每周一次以上的频繁微调（过拟合冲动）
改完才补回测（顺序违反）
Cherry-pick 指标（只看 Sharpe 不看回撤）

✅ 变更分四类，治理强度递增：参数（需完整回测）→ 回测引擎（需重跑历史对比）→ Bug 修复（需标注受影响的历史结论）→ 策略本质（需评估对资产配置框架的影响）。决策人就是你自己，无需审批，但所有变更必须每年 1 月被回顾。
